# Lab 3: Data Versioning with DVC and Google Cloud Storage

This lab versions a dataset with [DVC](https://dvc.org/) and stores the data in a Google Cloud Storage (GCS) bucket. It is my version of the Professor's DVC lab from the [course repository](https://github.com/raminmohammadi/MLOps). The reference lab uses a credit card dataset; this one uses the scikit-learn **Wine** dataset.

The idea is simple: Git tracks the code and a small `.dvc` pointer file, and DVC keeps the actual CSV in GCS. Checking out an older pointer file and running `dvc pull` restores the matching version of the data.

## 1. Objective

- Track a dataset with DVC instead of committing it to Git.
- Push the dataset to a GCS remote and pull it back.
- Create two dataset versions (V1 and V2) and switch between them using Git history.
- Generate both versions with deterministic scripts so they can be rebuilt exactly.
- Validate the data with pytest tests that need no cloud access.

## 5. Dataset versions

### V1: original Wine dataset

`create_dataset.py` loads the Wine dataset with `load_wine(as_frame=True)` and saves it to `data/wine.csv`.

- **178 rows, 14 columns**: 13 numeric features (such as `alcohol`, `malic_acid`, `flavanoids` and `proline`) plus `target`.
- `target` has three classes: 0, 1 and 2.
- The script checks the shape, missing values and target classes before saving, and refuses to write the file if anything is wrong.
- The data comes from a file bundled with scikit-learn, so the output is the same on every run and needs no network access.

### V2: added `alcohol_band`

`update_dataset.py` reads V1 and adds a categorical column, `alcohol_band`, using `pandas.cut`:

| Band | `alcohol` range | Rows |
|---|---|---|
| `low` | 0 < alcohol ≤ 12 | 22 |
| `medium` | 12 < alcohol ≤ 13.5 | 101 |
| `high` | alcohol > 13.5 | 55 |

- **178 rows, 15 columns**: all original columns are kept and `alcohol_band` is added at the end.
- The bins include their upper edge (the `pandas.cut` default), so exactly 12.0 is `low` and exactly 13.5 is `medium`.
- The script is idempotent: it drops any existing `alcohol_band` before rebuilding it, so running it more than once gives the same file.
- It checks for 178 × 15 and no missing values before overwriting `data/wine.csv`.

## 6. DVC configuration

The Git repository root is `MLOPS_labs/`, so DVC was initialized inside the lab folder with `--subdir`. The remote is set as the default in `.dvc/config`:

```ini
[core]
    remote = gcsremote
['remote "gcsremote"']
    url = gs://nishanth-mlops-dvc-lab3-2026/dvc-lab3
```

The commands used to set this up (run from `dvc_Lab3/`):

```bash
uv run dvc init --subdir
uv run dvc remote add -d gcsremote gs://nishanth-mlops-dvc-lab3-2026/dvc-lab3
```

### Where the data lives

`data/wine.csv` is **not** committed to Git. When you run `dvc add data/wine.csv`, DVC:

1. Stores the file in its local cache (`.dvc/cache`, which is ignored by Git).
2. Writes `data/wine.csv.dvc`, a small text file with the file's MD5 hash and size.
3. Adds `wine.csv` to `data/.gitignore`.

Git only tracks `wine.csv.dvc`, `data/.gitignore` and `.dvc/config`. `dvc push` uploads the cached file to the GCS bucket, and `dvc pull` downloads whichever version the current `.dvc` file points to.

## 7. Setup and reproduction

### Prerequisites

- Python 3.12 and [uv](https://docs.astral.sh/uv/)
- The [Google Cloud CLI](https://cloud.google.com/sdk/docs/install) (`gcloud`)
- Access to the GCS bucket: read for `dvc pull`, write for `dvc push`

### Install dependencies

```bash
git clone https://github.com/nishanth3112/MLOPS_labs.git
cd MLOPS_labs/dvc_Lab3
uv sync
```

### Authenticate with Google Cloud

DVC reads GCS credentials from Application Default Credentials, so no key file is needed:

```bash
gcloud auth application-default login
```

### Get the data

```bash
uv run dvc pull
```

This downloads the version of `data/wine.csv` that the committed `data/wine.csv.dvc` points to (currently V2).

> **Note:** The bucket `nishanth-mlops-dvc-lab3-2026` is private. To reproduce the lab with your own bucket, point the remote at it:
>
> ```bash
> uv run dvc remote modify gcsremote url gs://<your-bucket>/dvc-lab3
> ```
>
> Then rebuild the data locally with the scripts (section 8) and `dvc push` it.

## 8. DVC workflow

All commands are run from `dvc_Lab3/`.

### Create and track V1

```bash
uv run python create_dataset.py
uv run dvc add data/wine.csv
git add data/wine.csv.dvc data/.gitignore
git commit -m "Track Wine dataset V1 with DVC"
uv run dvc push
```

### Create and track V2

```bash
uv run python update_dataset.py
uv run dvc add data/wine.csv
git add data/wine.csv.dvc
git commit -m "Track Wine dataset V2 with alcohol_band"
uv run dvc push
```

### Check status

```bash
uv run dvc status      # local data vs. the .dvc file
uv run dvc status -c   # local cache vs. the GCS remote
```

## 9. Restoring V1 and V2

Each dataset version is tied to a Git commit through its `data/wine.csv.dvc` file:

| Version | Commit | Shape |
|---|---|---|
| V1 | `e30a6f7` | 178 × 14 |
| V2 | `f3ac460` | 178 × 15 |

To restore a version, check out that commit's pointer file and pull the matching data:

```bash
# Restore V1
git checkout e30a6f7 -- data/wine.csv.dvc
uv run dvc pull

# Restore V2
git checkout f3ac460 -- data/wine.csv.dvc
uv run dvc pull
```

To go back to the latest committed version:

```bash
git checkout HEAD -- data/wine.csv.dvc
uv run dvc pull
```

Only the pointer file changes in Git. DVC fetches the matching CSV from the cache or from GCS.

## 10. Tests

The tests live in `tests/` and run without Google Cloud credentials or network access. The checks on the real dataset read `data/wine.csv` without changing it. The script checks write only to pytest's temporary folders.

| # | Test | What it checks |
|---|---|---|
| 1 | `test_shape` | The dataset is 178 rows × 15 columns |
| 2 | `test_no_missing_values` | There are no missing values |
| 3 | `test_target_classes` | `target` contains exactly {0, 1, 2} |
| 4 | `test_alcohol_band_values` | `alcohol_band` exists and only contains `low`, `medium`, `high` |
| 5 | `test_alcohol_band_distribution` | The counts are low=22, medium=101, high=55 |
| 6 | `test_alcohol_band_matches_bin_boundaries` | Every row's band matches a hand-written version of the bin rules |
| 7 | `test_bin_edges_are_right_inclusive` | Edge values go to the right bands (12.0 → low, 12.01 → medium, 13.5 → medium, 13.51 → high) |
| 8 | `test_update_is_idempotent` | Running `update_dataset.py` twice on a temporary V1 file gives byte-for-byte identical output |

Tests 1–6 are in `test_dataset.py` and check the real V2 file. Tests 7–8 are in `test_update_dataset.py`. Test 7 builds V1 from scikit-learn's bundled copy, and test 8 points the update script at a temporary CSV, so the real `data/wine.csv` is never touched.

Run them with:

```bash
uv run dvc pull        # make sure data/wine.csv is present
uv run pytest tests -v
```

The tests expect V2. If you have restored V1, tests 1, 4, 5 and 6 will fail, which is expected.

## 11. Results

- **V1** was created with 178 rows × 14 columns and 0 missing values, tracked with DVC and pushed to GCS (commit `e30a6f7`).
- **V2** was created with 178 rows × 15 columns, 0 missing values and an `alcohol_band` distribution of low=22, medium=101, high=55, then tracked and pushed (commit `f3ac460`).
- Both versions were restored from GCS by checking out their `.dvc` files and running `dvc pull`.
- All 8 pytest tests passed against V2.
- After the test run, `data/wine.csv` still matched the MD5 hash recorded in `data/wine.csv.dvc` (`9fd1495487d226362816902a895f0388`, 13,344 bytes), confirming that the tests did not modify the tracked data.
